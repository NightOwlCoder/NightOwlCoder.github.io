The promise

A teaser can run ahead of the release, the way film teasers do. Every line here still points at something shipped or scheduled, not at a demo on one person's machine. Below: eight promises, the mechanism that holds each one, and three gaps still open.

You keep the last word.

The agents that write code cannot merge it, close it, or push to your main branch. That authority sits with one seat you can name, and it acts only on work the residents have verified. You hear that it's live. Nobody asks you to read a diff.

held by: task agents are hard-blocked from merge, close and push to main. Merging is an authority one seat holds, not a tool every agent has. Some things stay yours regardless: a fixed red list that always asks, and cannot be trained away

Some questions always come to you.

Deleting a disk, wiping a device, formatting a volume: these reach your phone every time, no matter how many times you said yes before. Everything else can be taught.

held by: a fixed red list that always asks and cannot be trained away. Ordinary consents can be remembered per project or everywhere

Two agents never fight over a file.

Each works in its own copy. No two may hold the same file at once. If the tests fail on the merged result, the merge is undone before you see it.

held by: worktree per task, a file-disjointness gate at dispatch, checks rerun on the merged tree and the merge reverted on failure

Passing tests are not proof.

Every piece of work names its evidence before the code exists: a test, an output, a screenshot. A second agent, whose only job is to disbelieve, checks each one. A test that would pass against the old code is a finding, not a pass.

held by: evidence-typed acceptance criteria in every task. A reviewer whose job puts the burden of proof on the coder

You always know where work stands.

A feature moves through named states, discussion to merged, and the engine owns the state. A hurried agent cannot skip one. You can read where anything is at any hour.

held by: an engine-owned state machine: discuss, planning, building, review, shipping, ready, merged, plus failure and abandonment

A stuck agent cannot hide.

A clock that is not an agent watches every agent. Silence with a turn open is a question. More silence ends the turn, keeps the finished work, and tells someone.

held by: the liveness sweep: one window to call it stuck, one to end the turn, and a wake to whoever supervises

Your project teaches its agents.

Rules you write into your repository are read at the start of every session. Skills, the residents' shared know-how, load on demand and travel with the install.

held by: project rules are a prompt layer read from the working directory. Skills are files, loaded by name

Questions climb. Only yours arrive.

An agent asks its lead, the lead asks the one running the project, that one asks the steward. You are the top of a pyramid that absorbs everything it can.

held by: the escalation pyramid: an ask climbs one level at a time, the engine wakes whoever must answer, and a phone channel is reserved for real decisions

Where it does not hold yet

The rules are not regression-tested.

Nothing yet runs a fixed suite of real tasks when a rule, skill or hook changes. Today you change a rule and learn from behavior.

The approved plan is not in the commit chain.

A plan lives in the engine and mirrors to the issue. The review pass cannot yet diff the code against the plan that was approved.

The overnight sweep has not run yet.

A nightly job exists to run the whole suite on a fresh main and wake the agent whose commit likely broke it. Its first real run is still owed. Until then the moment that describes it carries a label.
