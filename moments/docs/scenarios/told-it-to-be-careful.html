The story

The fear every agent product creates: you hand over the keyboard and hope. The answer is not a yes/no prompt on every keystroke; it is a ladder that asks a person only when a machine cannot answer, and remembers what the person said.

The four parts of this teaser

PartThis scenarioWhy

Rejected wording: "fine-grained permissions", "guardrails", "human in the loop". All three describe the mechanism. The moment is the person on a phone tapping once and being left alone afterwards.

What keeps it honest

Honest today on this machine, end to end: the ladder, the phone buttons, the teach affordance and the remembered rule all exist and run daily. Two things the copy must not imply: that the agent is safe (the red-list is a small set of disk-destruction shapes, everything else is a model's judgement, cached) and that "never asks again" is global (a taught rule is scoped to the folder or worktree it was taught in unless the person chose 🌍). The story shows the scoped tap on purpose.

The ladder, as the code documents it

StepWhat happensWhere
read-only short-circuit Tools that cannot damage anything (read_file, rg, file_info, gh-axi issue view, web_search…) auto-approve without asking a classifier. This is why the first two minutes of the story are silent. engine/sandbox.rs — decision 3
territory check A write path is canonicalized and must live inside the agent's worktree or its granted folders. Outside: rejected before any model is consulted. engine/sandbox.rs is_inside · sandbox_escalation.rs:433 write_is_granted
hard-block list Authority mutations that never run from a coder even if called safe (gh pr merge…). Returned as a tool error so the agent's loop adapts. engine/sandbox.rs — decision 1
classifier For run_command, an LLM classifies the command's shape. Results cached to disk so the same shape never costs a second call. crew/sandbox_classifier · ~/.ilha/db/safety_cache.json
tier 2 First refusal of an op in a session goes back to the agent as a synthetic refusal. Most rejections are typos or wrong paths; the agent self-corrects and no human hears about it. sandbox_escalation.rs — Tier semantics
tier 3 The agent retried the same op. Now a person is asked. Local presence: a ConsentRequired event the active client renders. Away: Telegram, with [Approve once] [Deny] [📚 Teach this WT] [🌍 Teach globally]. sandbox_escalation.rs — Tier semantics
red-list Skips tier 2 entirely — straight to the person on the first attempt. Shapes: rm -rf /, rm -rf ~, of=/dev/…, mkfs, shred /dev/, wipefs /dev/. Disk destruction, not git. engine/sandbox.rs:70 SKIP_TIER2_PATTERNS
teach A 📚 tap writes an allow-list row with a scope (this worktree, or global). Matching commands auto-approve silently afterwards without invoking the classifier. commands/allow_list.rs:18 · sandbox_escalation.rs:261
remember At a local gate, g/grant/remember writes a durable trust grant for the agent's name. Never offered for classifier-unsafe commands or MCP tools — remember_available on the event says whether the client may offer it. engine/events.rs ConsentRequired.remember_available

What a reply means

y / yes / ok / sure / go     approve this call
n                            deny
s                            approve this tool for the session
a                            approve this tool always (durable, consent_storage.json)
g                            approve + trust grant for this agent's name (when offered)
y5 / 5y                      approve this call and the next four
yolo                         approve everything for the rest of the session

Anything else goes to the consent-role model to be read as one of those. A reply that reads as nothing is a deny — the fail-loud default. (tools/consent/manager.rs, YES_RESPONSES at :17, parse_response_llm at :398.)

What does not exist yet

GapWhat it takes
"You taught me deletes in ~/exports last week, so I didn't ask." The allow-list is consulted silently. The story has the agent say why it did not ask. That is a rendering of an existing fact (the matched allow-list row) into the turn — an engine event the clients render, not agent prose. Small; not scheduled.
The phone card in the stranger's words Today the Telegram prompt shows the command. The story shows "delete 140 files in ~/exports". Same identifier-ban rule as scenario 01's receipt: the operation in the person's terms, the command as reference under it.
Trash, not rm The story promises "back from the trash". Nothing in the engine routes deletes through the OS trash. Either the copy drops the promise or a delete goes through a recoverable path. Product call.

Rejected, with reasons

ShapeWhy not
Approve every command That is the product people already have and hate. The point is the silence around the one question.
A permissions settings page Nobody configures permissions before they know what the agent will try. Teaching at the moment of the ask is the only time the person has the context.
"It's safe" It is careful, gated and remembered. Safe is a claim the red-list's six shapes cannot carry. The copy says what it does, not what cannot happen.
Regex deny-list Deleted in dd0caf3b (GH#518): substring scanning lost to ssh, bash -c and eval wrappers. The classifier judges the shape; the red-list keeps six hard lines.
