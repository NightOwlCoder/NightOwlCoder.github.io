The story

A chat tab dies with the tab. ilha's engine is a service on a machine, and every screen (terminal, browser, desktop app, phone) is a dumb terminal painting the same stream. A screen going away is not an event the work notices, because the work was never on the screen.

The four parts of this teaser

PartThis scenarioWhy

Rejected wording: "runs in the background", "the work ran on while the lid was shut". The first is what every product says. The second was this scenario's first draft and it is false for a person whose only machine is the laptop, see the next section. The copy now says where the agent lives and lets the reader draw the consequence.

What keeps it honest

Two install shapes, and the teaser is true for one of them.

ShapeLid closesWhat the copy may say
engine on a machine that stays on
desk PC · mini PC · home server · a small cloud box
laptop and phone are screens		 Nothing happens to the work. The screen is gone; the turn continues; the phone picks it up. Everything in the card. This is the shape on this network: the engine runs as a Windows service on a desktop and as a launchd service on a Mac, both reached from a phone over a private network tunnel.
one laptop, engine installed on it The engine sleeps with the lid. Nothing is lost (sessions are on disk and the reconnect replays the transcript) but the work pauses, and a turn that was mid-stream when the network went away ends when the connection does. Nothing is lost; pick up where you left off. Never the work ran on.

So the site, or the installer, has to know which shape the person has before this card is shown to them as a promise, or the release offers the first shape as a thing you can buy (a small cloud box ilha provisions), which is a product question and not a copy fix. The "while you were away" paragraph is the resume briefing the engine already writes; its wording is the engine's and reads as the agent's summary.

part three

How it is built

Measured on this machine and on main. The mechanism exists; the gaps are reach and the single-laptop truth.

drawn against: scripts/mac/install-serve.sh · scripts/install.ps1 (NSSM) · serve/ws_mux.rs · engine/events.rs Catchup + LifecycleContext · chat/storage.rs · chat/session.rs · the network doc under docs/ · GH#1075

What exists

Claim in the storyMechanismWhere
The agent is a process on a machine, not a tab The turn runs in the daemon. A client disconnect logs client disconnect — N session(s) preserved and cancels nothing. serve/ws_mux.rs:1503
The daemon is always there macOS: launchd plist with RunAtLoad and KeepAlive. Windows: an NSSM service registered by the installer, auto-start on boot. Both restart the process if it dies; neither can run while the machine sleeps. scripts/mac/install-serve.sh:155–157 · docs/INSTALL.md:15–36
Open it anywhere, same conversation Any client sends subscribe; the engine answers with SessionEvent::Catchup { messages, .. } — the same event /redraw re-emits. 4,544 session files on disk here, all reachable this way. engine/mod.rs:6325 · ws_mux.rs:2685 · chat/storage.rs:633
"While you were away…" On resume the engine injects a LifecycleContext with a display text; the brain adds a <brain-briefing> of related work since. Rendered by all three clients. engine/events.rs LifecycleContext · brain/pulso.rs
"Which one first?" — it remembered where it was Session scratchpad, engine-written at the end of every turn, survives compaction. Capped at 8,192 bytes so it stays a cursor, not a database. chat/session.rs:273 SCRATCHPAD_BYTE_CAP
Phone reaches the engine at home On this network: a private tunnel, two connectors per host, the phone resolves the daemon by name. Configured by hand. the network doc under docs/, topology section

What does not exist yet

GapWhat it takes
The single-laptop truth, stated by the product Nothing today tells a one-laptop user that the engine sleeps with the lid. The installer knows whether it is installing onto the only machine; the door can say which shape it is running in. One flag, one sentence.
A mid-stream turn surviving a sleep When the machine sleeps mid-turn the model stream dies with the network. Transient errors retry (ProviderRetry); a non-retryable one ends the turn and, for a named resident, today wakes nobody (GH#1075). On wake the person sees the partial turn in the catch-up, with no marker saying "this ended because you slept". Needs the terminal marker, then a resume from the last complete tool result.
A stranger's phone reaching their engine A hand-configured tunnel here. A stranger needs a relay, a documented tunnel, or the engine on a cloud box. The release-sequence installer question.
A Mac installer install-serve.sh presumes /usr/local/bin/ilha from a source build. install.ps1 does the whole job on Windows. Mirror it.

Rejected, with reasons

ShapeWhy not
"The work ran on while the lid was shut" True on an always-on box, false on a lone laptop. A teaser must not depend on a fact about the reader's hardware the reader has not told us.
"Runs in the background" Every product says it. The moment is the device change plus the authored catch-up.
Show a sync spinner / "restoring session…" There is nothing to restore. The engine never lost it. A spinner would be a lie about the architecture.
Promise cloud sync between machines ilha is one engine per person; every device talks to it. Selling multi-engine sync sells something that does not exist.

Checklist

  1. Disconnect preserves the turn. [evidence: L1 — a client that drops mid-stream, then re-subscribes, receives the full turn in Catchup; exists today as the ws_mux "client disconnecting tears its WS connection" tests]
  2. Resume briefing renders on all three clients. [evidence: the terminal_parity_events vitest, plus the terminal's chat_render arm]
  3. The door states the install shape. [evidence: new — a one-laptop install shows "your agent sleeps when this machine does"; screenshot]
  4. Sleep mid-turn ends cleanly and is marked. [evidence: new — L1: the provider stream is cut mid-turn; catch-up carries a terminal marker naming the cause]
  5. A stranger's phone reaches their engine. [evidence: fresh install on an always-on box, phone on cellular, opens the PWA and sees Catchup — the installer item]
