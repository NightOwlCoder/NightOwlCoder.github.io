Two agents editing the same file, and the second one quietly undid the first?

Ours never share a working copy. Each gets its own, they may not touch the same file at once, and nothing lands until the tests pass on the merged result — or the merge is undone before you see it.

the beat: a merge that fails its tests is reverted, not shipped and apologized for

Three rules, all mechanical. Every agent works in its own copy. Two agents may not hold the same file at the same time — the second is refused before it starts. Merges happen one at a time, and the tests run again on the merged state; red means the merge is undone. None of these is a request to the agents. They are things the agents cannot do otherwise.

Rejected wording: "isolated sandboxes", "conflict-free", "safe parallelism". The first is mechanism, the second is false (conflicts happen; they go to a fresh agent), the third is a claim. The copy names what a visitor has seen go wrong and what happens here instead.

What keeps it honest

All three rules exist and run on this machine daily (52 worktrees live at the time of writing). What the copy must not imply: that conflicts cannot happen. They do; a conflicting merge is handed to a fresh agent that reads both sides, not to the coder who wrote one of them. And "waiting" in the story is the real behaviour: the engine refuses the overlapping dispatch and it runs later, it does not run in parallel and get sorted out afterwards.

The three fences

RuleMechanismWhere
Every agent works in its own copy A run gets a git worktree of its own (WORKTREES_SUBPATH in feature.rs); each coder task gets an ac/ branch. Writes outside the worktree are rejected before any model is consulted (scenario 03, territory check). feature.rs:15 WORKTREES_SUBPATH · engine/sandbox.rs is_inside
Two agents may not hold the same file A task-list dispatch is refused before the actor spawns when its files_to_modify overlaps an in-flight sibling's on a non-shared file, a blocker is unmerged, or the dependency graph is cyclic. On pass the row is stamped dispatched inside the gate's critical section, so a concurrent overlapping dispatch sees the claim and refuses — no window between check and claim. engine/actor_driver.rs:651 gate_and_claim_task_list_dispatch
Merges are one at a time, and tests rerun on the merged state Merges are serialized so interleaving cannot produce a half-merged tree. After a clean merge, the coder card's success checks run again on the merged sede state; if they fail, the merge commit is reverted and checks_failed: true comes back with the output. commands/merge_task.rs — Post-merge Validator-2 (SPEC_ACTOR_RUNTIME §15 item 16c)
A conflict goes to a fresh agent On conflict the conflicting files are returned and the sede dispatches the github card to rebase — not the authoring coder, which carries the costliest context in the run for what is usually a mechanical rebase. commands/merge_task.rs:6–10
Merge authority is not the coder's Hard-block list: gh pr merge and other authority mutations never run from a coder even if a classifier calls them safe. engine/sandbox.rs — decision 1

Rejected, with reasons

ShapeWhy not
Let the agents coordinate ("B, please don't touch parser/") A request an agent can forget under context pressure is not a fence. The gate refuses the dispatch; nobody has to remember anything.
Run C in parallel and merge-sort the conflict later That is the failure being sold against. Refusing the overlap up front costs one serialization; resolving it afterwards costs a rebase and a re-review.
Trust a green per-branch test run B's tests passed alone. The bug was in the combination. Only the merged state can answer whether the merge is good.
Ship the merge and file a fix The person's copy would be broken between the ship and the fix. Revert first is the only order in which "nothing you have is broken" stays true.

Checklist

  1. Overlapping dispatch refused before spawn. [evidence: existing gate tests in engine/actor_driver.rs; a concurrent-dispatch race test]
  2. Red on merged state reverts the merge. [evidence: existing merge_task tests — checks_failed path leaves HEAD at pre-merge]
  3. Conflict dispatches github, not the coder. [evidence: existing merge_task conflict tests]
  4. Handoff card shows "waiting — overlaps X" and "merge undone — N tests". [evidence: new — shared component renders both states from engine facts; screenshot at phone width]
  5. "Nothing is broken" is derivable. [evidence: new — an engine query over the run's merge history answers it; L1 test]
