part one

The story

The most common way an agent fails is quietly. A spinner that never stops. A turn that ended on a provider error and told nobody. The person finds out by looking, hours later. The cure is a watchdog written in code, not in a prompt.

The spinner that would have spun all night

Slow, not stuck. It's been running your test suite for 6 minutes, the suite takes about 9. It has produced output in the last minute. I'll say something if that changes. You don't need to watch it.

slow: measured against what it is doing, not against your patience

I ended the turn, kept the two sections it had already written, and it will restart from there in the morning rather than from scratch. Nothing for you to do. Telling you so you don't find a half-report at breakfast and wonder.

🌶️

stuck: ended by the clock, kept what was finished, restarted from there, and said so

Two different answers to the same question, and a machine tells them apart. "Slow" is a turn that is still producing; the answer names what it is doing and how long that usually takes. "Stuck" is silence past a fixed clock; the answer is that the turn was ended, the finished work kept, and a person told, before the person asked.

Rejected wording: "self-healing", "resilient", "never gets stuck". Agents get stuck; that is the premise. What is sold is that a clock notices before you do, and the answer you get distinguishes slow from stuck instead of saying "still running…".

What keeps it honest

The clocks exist and run: 180 seconds of silence with a turn open flags a wedge; 300 seconds past that aborts the turn so it ends with exactly one terminal state; three continue-nudges without progress declares a run STUCK and wakes its supervisor. The two-deaths incident in GH#1075 is the reason the copy can say "nothing waits for you to notice" only about dispatched work today; for the long-lived named agents the same guarantee is GH#1088 and still open. The story uses an overnight job on purpose: that path is covered. Pepper's "slow, not stuck" answer quotes fields the engine already writes (in_turn, since, waiting_on, open_gate); the "suite takes about 9" comparison is not yet a fact the engine holds.

part three

How it is built

Measured on main. The clocks and the salvage exist. The stranger's sentence is a join over facts already written; the one missing fact is "how long this usually takes".

drawn against: engine/mod.rs liveness constants · engine/sweeps.rs · commands/condition.rs · engine/actor_driver.rs (salvage) · GH#1075 · GH#1088

The clocks

ConstantValueMeaning, per its own doc comment
WEDGE_AFTER180 s Zero events with a turn in flight before the liveness sweep flags a genuine wedge. Deliberately far above the old 45 s client threshold: a long cargo test shows as running/checks, not idle, so this only fires when the agent truly produces nothing while its turn lives.
STALL_KILL_AFTER300 s Past stalled: true, a zero-progress dispatched turn has an await that will never return (mid-stream provider hang). The sweep aborts the future so the turn fails up to its caller — exactly one terminal, never a park.
SEDE_CONTINUE_BUDGET3 Continue nudges without feature-state progress before a run is declared STUCK and its supervisor is woken. "Budget, not faith."
SEDE_CONTINUE_AFTER_BACKGROUND600 s Background runs continue on a slower clock while a priority run holds the provider; they still make progress.

All in crates/ilha/src/engine/mod.rs, next to each other. The sweep that reads them is run_sede_drive_sweep. None of this is a prompt instruction; a model cannot forget it.

What survives a kill

ClaimMechanismWhere
"kept the two sections it had already written" A task is one failure unit; its git branch survives for salvage. A failure wake counts the surviving commits, and the doctrine is salvage-first: inspect the branch before re-dispatching. engine/actor_driver.rs:1049 · :4757 salvage_probe
"restart from there rather than from scratch" continue_task with the dead task's handle wakes the same agent in its worktree with conversation, branch and commits intact. dispatch_task continue_task · Layer 1 customer rules
"someone is told" Stall and STUCK wake the run's supervisor via wake_porto_on_sede_event; the pushed line to a phone obeys the [08:00, 23:30) window and folds into the morning digest otherwise — which is why the story's 02:14 message is read at 07:30. engine/mod.rs wake_porto_on_sede_event · notify_operator.rs:16

What does not exist yet

Rejected, with reasons

ShapeWhy not
Ask the agent if it is stuck A stuck agent cannot answer; a slow one will say "still working" whether or not it is. The clock is outside the agent for exactly this reason.
A 45-second timeout The old client threshold. A real test suite is quiet for longer than that; killing it is a false positive that costs the run. 180 s with a "producing output" check is the measured floor.
Kill and restart from scratch Throws away paid-for work. Salvage-first: the branch survives, the same agent resumes with its context.
Page the person at 02:14 The push window is [08:00, 23:30); outside it folds into the digest. Status is never a reason to wake someone. The story reads the message at breakfast on purpose.
