The story

The most expensive sentence in AI-assisted coding is "all tests pass". It is true and it proves nothing when the test was written by the same hand as the code, to pass. The fix is not a better model. It is a second agent with the opposite incentive, a contract that names the evidence up front, and a gate that will not open on a claim.

Rejected wording: "quality gates", "AI code review", "self-verifying". What is sold is adversarial structure: the reviewer is rewarded for finding the hole, the criteria are typed before the code exists, and the merge refuses a claim.

What keeps it honest

The reviewer's rule is quoted from its card: "a test whose assertion holds even against the old code … if a passing result rests on a trivially-satisfiable assertion, that's a [P1] finding", and "every acceptance criterion carries its typed evidence (test | output | screenshot) … a gap is a [P1] finding → REQUEST CHANGES". P0/P1 → REQUEST CHANGES is the card's verdict mapping. The merge revalidation and revert are in merge_task. Twenty of the last forty merged PRs in this repo carry a machine review as well. The exporter and PR #212 are fiction; the review exchange is the shape the cards produce.

What does not exist yet

GapWhat it takes
"both new tests fail without the change" as a checked fact Today the reviewer may run the test on the parent; the card asks for it but the engine does not enforce it. A validation step that runs new test names against the task's base commit and records pass/fail is a small addition to ilha-validation, and it turns the strongest sentence in the receipt into a measurement.
Pepper's 11:52 sentence PR number, diff size, criteria count and suite result all exist as facts; the outcome sentence is the receipt from scenario 01 (ask key outbound, outcome joined at the door).

Rejected, with reasons

ShapeWhy not
One agent that codes and reviews itself Same incentive on both sides. The reviewer is a different card with a disbelieving brief; that is the whole mechanism.
A fresh reviewer per round Findings go back to the agent that raised them and to the coder that wrote the code; both keep their context. Cheaper and it cannot re-find settled points.
Merge on APPROVE alone APPROVE is a judgment; the merged-state check is a measurement. A reviewer can be right about a branch and wrong about the merge.
Show the person the review thread The round trip is the residents' work. The person is paged for decisions, never for status; they get one PR with the proof attached.

Checklist

  1. Task criteria require an evidence type; a missing one fails the task. [evidence: existing task_list tests]
  2. merge_task reverts on check failure and returns the output. [evidence: existing merge_task tests]
  3. ship_feature refuses with unchecked scope and no remainder issue. [evidence: existing ship_feature tests]
  4. Quarantine exonerates a diff-unrelated flake; diff gate skips a byte-identical tree. [evidence: existing ilha-validation tests]
  5. New tests are run against the base commit and their fail-then-pass is recorded. [evidence: new — validation test with a vacuous test fixture; output]
